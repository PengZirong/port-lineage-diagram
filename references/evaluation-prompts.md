# Skill 调用评估样例

这些是给 Agent 的任务测试题，不是声称已在全部 Agent 客户端执行过的基准成绩。

## 1. 常见案例

> 使用端口式数据流图，画一笔订单的价格分支和运费分支如何汇合。订单号不参与金额计算，但必须解释最终来源。只保留必要字段，输出交互 HTML 和 PNG。

应触发本 Skill。使用通用订单案例，保留旁路透传，配置显式出现，不插入医疗字段。

## 2. 真实项目

> 根据我提供的导入模块代码，画每个最终输出字段在哪一步生成、沿途如何转换。代码里找不到来源的字段不要猜。

先读代码，再建 `mode=grounded` 模型。未知来源标 unknown；缺少证据不能写 verified。
不能把 `evidence` 的存在当成已经实际读过文件。

## 3. 跨领域复用

> 输入文件名和文件内容，解析行数，另外从系统时钟拿接收时间，再汇合成导入结果。用同一种画法。

只换 JSON，不改查看器。文件名旁路，文件内容派生行数，接收时间来自 runtime。
预置 `examples/file-import.json` 验证这类复用。

## 4. 非线性与循环

> 缓存命中走缓存，未命中调用 API，二者合并；失败时重试最多两次。最终字段保留命中路径来源。

明确命中条件、未命中条件、guarded choose 与重试控制语义；静态候选来源不冒充某次真实执行。
数据重试版本需要展开，不能声称当前模型天然支持未版本化数据环。

## 5. 字段过多

> 表有 80 列，但我只关心 total、currency、order_id。图中别再出现一大堆不相关字段。

从这三个输出逆向求依赖闭包，删除范围外字段。不能为简化而丢 total 的配置、汇率选择键或单位说明。
当前查看器没有动态字段折叠；不能生成假的折叠按钮。

## 不应强行触发

仅要 ER 图、类图、时间进度表、流量桑基图或机构组织图时，使用相应方法。
用户明确要求其他绘图规范时，不以本 Skill 替代他们指定的格式。
