# 绘图规则

## 一张图，而不是两个区域拼接

同一处理节点包含字段；连线从上游输出端口直达本节点输出字段的依赖接入口。
正常阅读不依赖另外一张流程总览。右侧字段说明不能掩盖主图没有画出的来源。
“流程骨架”只是相同节点与依赖的折叠视图，不是一套独立维护的图。

## 紧凑端口语义

本版本采用“输出字段映射卡片”：左端是该行的输入依赖汇入口，右端是该行的输出。
例如 `商品金额` 的左端接入数量和单价，规则写 `数量 × 单价`。
它不是说“数量输入”和“单价输入”被合成一个同名标量，也不是完整 UML 活动图输入 / 输出 Pin。

需要严格区分处理函数的输入契约与输出契约时，在同一个节点内增设输入区和输出区，连线仍需有精确端口。
不能声称当前紧凑查看器已实现复杂的输入区折叠或端口拖拽；这些是可后续扩展的界面能力。

## 视觉系统

底色浅灰蓝，节点白底细边框；卡片标题轻量分色，避免大面积强色。
源数据蓝色，处理青绿色，配置 / 参考数据紫色，输出浅琥珀色。
字段值依赖用带箭头的实线；查找选择键用紫色短虚线；条件依赖用灰色点线；显式控制边用灰色长虚线。

颜色说明的是该次处理，不永久给字段染色：计算生成字段在下一步透传，应标“透传”而非再次“新生成”。
字段操作同时有中文标签，不能只靠颜色判断。

样式基线：标题 17px，中文字段 13px，英文代码名 11px，辅助规则 9.5–11px，字段行 70px。
完整画布保持矢量，可缩放；窄屏允许画布滚动，侧栏放到下面，不把 7 个节点挤成细小字块。
长文字在卡片上适度缩略，悬停 title 和侧栏必须保留完整原文；关键含义不能只剩省略号。

## 布局顺序

1. 先放输入、主要处理、关键输出，保留真实依赖方向。
2. 独立分支上下放置；配置紧邻消费它的分支，不插入主流程伪造先后顺序。
3. 预留跨分支透传的走线通道；字段没经过计算分支就直接跨过，不凭空画成从分支产生。
4. 只对长边设置少量绕线坐标。不能修改来源端点以迁就布局。
5. 默认以完整图确认结构，点击字段进入聚焦模式减轻交叉干扰。

自动检查避免边穿过无关节点，但不保证任意连线交叉都被最小化。
交叉与汇合不同：只有在目标端口才是字段合并依赖；中途交叉不画连接点。

## 字段数量

只保留目标输出的必要依赖闭包。
不为了“像生产系统”随意添加 UUID、时间戳、source_file、status、version、score 等字段。
确实需要系统生成值时，它的时钟、随机数、常量或配置同样必须作为来源声明。
不要用一个模糊的 `data` 或 `metadata` 字段藏起决定计算结果的核心子字段。
输入本来就是明确的映射对象时，可以保留它的真实类型，例如 `map<区域,运费分>`。

透传很多时可以实施“折叠若干透传字段”的扩展，但必须由真实关系计算数量，逐项可展开，来源覆盖校验不能跳过。
当前随包查看器不伪装拥有字段折叠功能；它通过限制图的范围与聚焦高亮保持简洁。

## 经常出错的地方

| 错误 | 修正 |
|---|---|
| 只画新增的字段，继承字段突然出现 | 每个输出必须有直接依赖或合法根来源。 |
| 在最终汇合再次把全部字段标“新增” | 按本次操作区分透传与计算。 |
| 同名字段使用同一高亮标签 | 按完整节点.字段 ID 遍历依赖。 |
| 字典箭头从计算结果指向字典 | 统一来源 → 使用者；不复制 PROV 的反向谓词惯例。 |
| 给所有继承字段标“来自标准输入” | 记录直接上游，再自动追到最初来源。 |
| 外部配置没画，公式却使用了阈值 | 配置也是根节点。 |
| 未确认来源自动算进 100% | unknown 以明显状态显示，不能通过严格构建。 |
| 把独立分支画成强制串行 | 按真实依赖排布，并说明执行语义的已知边界。 |
| 只检查 DOM 标签数量就称完成视觉验收 | 真实截图、检查端点和遮挡，并亲自查看图片。 |
| 更换案例仍残留“患者 / 结算”等业务词 | 模板文案保持通用，业务词来自 JSON。 |
